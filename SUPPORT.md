# Support

## Where to get help

| Need | Where |
| --- | --- |
| Bug or feature request | [GitHub Issues](https://github.com/idexal/idexal/issues) |
| Security report | See [SECURITY.md](SECURITY.md) — email, not issues |
| Licence, deployment, partnership | <contact@idexal.com> |
| Release history | [CHANGELOG.md](CHANGELOG.md) and the [Releases page](https://github.com/idexal/idexal/releases) |

## Before you open an issue

Please include:

1. **Version and channel** — from the application's About screen, for example
   `4.0.0 Alpha`.
2. **Platform** — Windows, macOS or Linux, and the architecture.
3. **Surface** — desktop, browser client, terminal, or a phone controlling a
   desktop session.
4. **What happened and what you expected**, with the exact message text if an
   error was shown.
5. **Steps to reproduce**, and whether it happens every time.
6. **When it started** — after an update, after installing a plugin or skill, or
   with a particular project.

## Collecting diagnostics

Application data, settings and logs live under your Idexal data directory
(`.idexal` inside your home directory by default, or wherever
`IDEXAL_DATA_BASE_DIR` points). Attach the log for the failing time window rather
than the whole directory.

**Remove anything you consider sensitive before attaching**: tokens, API keys,
private repository contents, and real user data. Issues on this repository are
public.

## What we do not support here

Questions about your own model provider's quota, billing or API keys are usually
answered faster by that provider. If Idexal reports a provider error, the message
states what Idexal could not do; take that text to the provider if the cause is on
their side.
