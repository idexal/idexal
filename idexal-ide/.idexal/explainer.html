Idexal IDE — Architecture & Changes

A visual explanation of the project structure, the changes made, the test contract, and what was simplified.

1. System Architecture

The IDE is a three-layer system: a React UI renders in Electron, communicates with a Node.js main process for real file I/O, and optionally bridges to a Rust engine for agent orchestration and code parsing.

Key insight: The React renderer talks to the real file system through Electron IPC (contextBridge → ipcRenderer → ipcMain → fs). In browser-only mode (Vite dev server without Electron), it falls back to a mock file tree — this is why the file explorer works in the Preview tab.

Bug fixed: Earlier, messages were added to both the Zustand agentStore and local React state, causing every message to appear twice. The fix uses only local state — the store is no longer involved in the chat message lifecycle.

4. File Open: End-to-End Data Flow

What happens when a user clicks App.tsx in the sidebar file explorer:

Click on file in Sidebar
→
handleFileClick(filePath)
→
fileSystemService.readFile(path)
→
IPC: ipcRenderer.invoke('read-file')
→
Main: fs.readFileSync()
→
useEditorStore.openTab({content})
→
Monaco renders with language detected

In browser mode, readFile returns mock content for known files (App.tsx, package.json, README.md) and a placeholder for everything else. The tab ID uses Date.now()-counter to prevent collisions.

6. Context Window: How Messages Are Packed

When sending a message to the AI, the context window manager assembles messages in this order, respecting token budgets:

PriorityContentBudget Cap
highSystem prompt (agent personality)Always included
mediumProject context (file structure, languages)≤ 30% of available tokens
mediumRelevant file contents≤ 60% of available tokens
lowConversation history (chronological order)Fills remaining 80%
highCurrent user messageAlways included, always last

Bug fixed: History was previously reversed then pushed in reversed order, producing newest-first. Now messages are unshifted during selection to maintain chronological (oldest-first) order, which is what APIs expect.
