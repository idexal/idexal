# Idexal — مخططات التنفيذ لـ Claude Code

> هذه المخططات كُتبت لتُنفَّذ حرفياً بواسطة **Claude Code** (أو أي وكيل برمجة).
> القسم الوحيد الذي يكتب الكود هو المنفّذ؛ وثائق التصميم في
> [docs/design/](../design/README.md) هي المرجع، وهذه المخططات هي الخطة.

## بروتوكول التعاون (اقرأه أولاً)

1. **ابدأ بقراءة التصميم** — قبل أي تنفيذ، اقرأ:
   - `docs/design/README.md` (الفهرس والمبادئ)
   - الوثيقة المرتبطة بخطتك (مذكورة في كل مخطط)
   - `docs/adr/0001-pivot-to-rust-electron.md` (القرارات المعمارية)
2. **اتبع المخطط ترتيبياً** — لا تتخطَّ خطوة، لا تنفّذ ميزة من خارج المخطط.
3. **لا تعدّل الملفات خارج المخطط** إلا للضرورة المباشرة (أخطاء تحقق).
4. **لا تُغيّر سلوكاً مُختبَراً** — كل اختبار موجود يجب أن يبقى ناجحاً:
   ```bash
   cd core && cargo test          # 33 اختباراً يجب أن تبقى خضراء
   cd app && npm run typecheck    # فحص الأنواع إلزامي قبل أي بناء
   ```
5. **تحقق بعد كل خطوة كبيرة** — تشغيل الفحوصات، لا الاكتفاء بالكتابة.
6. **عرّف "تم" بمعيار القبول** — كل مخطط ينتهي بقسم "معيار القبول". لا تعلن
   إنجازاً لم تُثبته بأمر فعلي (مبدأ verification-before-completion).
7. **التوثيق** — بعد الإنجاز: حدّث `ROADMAP.md` (نقل العنصر من المتبقي إلى المنجز)
   و`CHANGELOG.md`. لا تُعدّل وثائق التصميم دون تسجيل ADR جديد.
8. **الأمان** — اتبع دائماً `docs/design/07-permissions.md`: لا Git تعديلي بدون
   تأكيد صريح، لا مفاتيح API تُرسل للواجهة، كل مسار عبر الفحص الحدودي.

## حالة المحرك الحالية (سياق المنفّذ)

- `core/` — Rust: حلقة وكيل كاملة، تعدد وكلاء (مخطط←منفّذون متوازون←مراجع)،
  Fallback مع cooldown، ذاكرة SQLite، 4 أدوات، أوامر `stream|agent|providers|config|test|memory`.
- `app/` — Electron: شجرة ملفات، تبويبات Monaco، طرفية stdio، Git قراءة فقط،
  معاينة webview، لوحة وكيل حيّة.
- `cli/` — `idexal` بأوامر: run/agent/review/providers/config/test/memory.
