# المخطط 003 — تعدد المهام المتزامنة

> **المنفّذ**: Claude Code · **المخطط**: Idexal
> **المرجع التصميمي**: `docs/design/04-features.md` + `docs/design/05-agents.md`

## الهدف

أكثر من **محادثة/مهمة وكيل واحدة في آنٍ واحد**: المستخدم يرسل مهمة جديدة بينما
أخرى ما تزال تعمل، وكل مهمة لها سجلها المستقل ولوحة مهامها، مع إمكانية إيقاف
واستئناف. **العمود الفقري موجود** (النواة عملية منفصلة لكل تشغيل) — المطلوب
إدارة الجلسات في الواجهة وmain.

## الوضع الحالي

- `window.idexal.runTask(task, onEvent, mode)` تنشئ قناة فريدة وتُشغّل عملية
  نواة جديدة — **كل استدعاء جلسة مستقلة بالفعل** في main (كل child process).
- المشكلة: الواجهة تعرض **سجلاً واحداً** (`#agent-log`) وزر إرسال واحد —
  مهمة ثانية أثناء تشغيل أولى تخلط البثّ في نفس السجل.

## الخطوات

### الخطوة 1 — إدارة الجلسات في renderer

في `app/src/renderer/index.ts` حوّل السجل إلى **جلسات**:

```ts
interface AgentSession {
	id: string;
	task: string;
	stop: () => void;
	running: boolean;
	lines: HTMLElement[];   // عناصر سجل هذه الجلسة
}
const sessions = new Map<string, AgentSession>();
let activeSessionId: string | null = null;
```

- `send()` تنشئ جلسة جديدة بدلاً من الكتابة في سجل عام:
  - أنشئ حاوية سجل جديدة (`#agent-log` لكل جلسة أو سجل واحد بعناوين جلسات —
    **الأفضل**: سجل واحد بفاصل "── مهمة جديدة ──" مع استبدال السجل عند تنشيط
    جلسة من قائمة جانبية).
  - أعد كتابة `send()` لتأخذ `sessionId` وتبثّ أحداثها داخل حاوية تلك الجلسة.
- **قائمة الجلسات**: أضف شريط تبويبات صغير فوق لوحة الوكيل (أو استخدم لوحة
  "مهام الوكلاء" الحالية) يعرض الجلسات النشطة: النقر يفعّل عرضها، زر × يوقفها.
- **إيقاف**: `session.stop()` (المُرجِع من `runTask` — موجود) يقتل بثّ تلك
  الجلسة فقط. زر "إيقاف" بجانب الحالة عند التشغيل.

### الخطوة 2 — منع التداخل

- `setRunning` يجب أن يعمل **لكل جلسة** لا لزر الإرسال العام (زر الإرسال يظل
  متاحاً دائماً — يمكن إرسال مهمة ثانية).
- `renderPlan`/`markStep` يجب أن تستهدف جلسة المهمة النشطة (`data-session` على
  صفوف الخطط).
- **تحذير**: لا تُسقط أحداث الجلسة الخلفية — كل `onEvent` يُوجَّه لحاوية جلسته
  عبر closure مغلق عند الإنشاء.

### الخطوة 3 — (اختياري، إن أردت عمقاً أكبر) تعدد في النواة

النواة تعالج مهمة واحدة لكل عملية — وهذا **كافٍ ومقصود** (عزل كامل). لا حاجة
لتغيير في `core/`. إن أردت تقييداً للتوازي العالمي، أضف عدّاد جلسات نشطة في
main (حد أقصى مثلاً 3) مع طابور — أبقِه اختيارياً.

### الخطوة 4 — الأنواع والأنماط

- أضف `sessionId` إلى `declare global` لواجهة `runTask` (معلمة اختيارية ثالثة
  أو رابعة) — أو ابقِ الواجهة كما هي واستخدم closure (الأبسط).
- أنماط CSS لتبويبات الجلسات/الأزرار بنفس التوكينات.

## التحقق

```bash
cd app && npm run typecheck && npm run bundle
# يدوياً: أرسل مهمة "اشرح البنية" ثم فوراً مهمة ثانية — يجب أن يُبثّ كلٌّ في
# حاوية مستقلة، والتبديل بينهما لا يخلط المحتوى.
```

## معيار القبول

- [ ] مهمتان متزامنتان تعملان معاً، لكل منهما سجل ولوحة خطة مستقلة.
- [ ] إيقاف جلسة لا يؤثر على الأخرى.
- [ ] زر الإرسال متاح دائماً (لا تعطيل عام أثناء التشغيل).
- [ ] `typecheck` نظيف · `bundle` ناجح.
- [ ] `ROADMAP.md` محدَّث (تعدد مهام متزامنة → منجز).
