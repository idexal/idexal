# المخطط 004 — الوكلاء الفرعيون (Subagents)

> **المنفّذ**: Claude Code · **المخطط**: Idexal
> **المرجع التصميمي**: `docs/design/05-agents.md` (قسم "وكلاء المستقبل")

## الهدف

أداة `delegate` داخل النواة: المنفّذ (Executor) يفوّض مهمة جزئية إلى **وكيل فرعي**
بجولة منفصلة (نفس النواة، نفس المزودين، نفس الأدوات وفق صلاحياته)، ثم يعود
بنتيجة موجزة تُدمج في محادثة المنفّذ. الأساس جاهز: `agent::run` معزولة وقابلة
للاستدعاء المتكرر.

## الوضع الحالي

- `core/src/agent.rs` — `agent::run(...)` تعمل لأي prompt/task/أدوات — **أساس الوكيل
  الفرعي جاهز** (المخطط والمنفّذون والمراجع يستخدمونها بالفعل).
- `core/src/tools.rs` — `definitions()` + `dispatch()`: إضافة أداة = خطوتان.
- لا يوجد بعد: أداة `delegate` ولا نظام تعريف أدوار.

## الخطوات

### الخطوة 1 — أداة `delegate` في tools.rs

- أضف تعريفاً في `definitions()`:
```json
{
  "name": "delegate",
  "description": "تفويض مهمة جزئية إلى وكيل فرعي يعمل بجولة منفصلة ثم يعود بملخص موجز.",
  "input_schema": {
    "type": "object",
    "properties": {
      "task": { "type": "string", "description": "المهمة الجزئية الدقيقة للوكيل الفرعي" },
      "context": { "type": "string", "description": "سياق مختصر مفيد (مسارات، قرارات سابقة)" }
    },
    "required": ["task"]
  }
}
```
- **قيد حرج**: `delegate` غير متزامنة داخل `dispatch` المتزامن — الحل التصميمي:
  تُنفَّذ عبر **إعادة الدخول** في `agent.rs` وليس داخل `dispatch` (انظر الخطوة 2)،
  و`dispatch` تعيد `{ok:false, output:"delegate is handled by the agent loop"}`
  حتى لا تُنفَّذ خاطئاً.
- لا تُضف `delegate` إلى `read_only_definitions()`.

### الخطوة 2 — دعم إعادة الدخول في agent.rs

- في `agent::run`، عند تنفيذ كل `ToolCall`، افحص:
  - إن كان `name == "delegate"`: حلل الـ args، واستدعِ `agent::run` **بشكل متكرر**
    بنظام prompt وكيل فرعي (`SUBAGENT_PROMPT` جديد: "وكيل فرعي — نفّذ المهمة
    المفوَّضة فقط وأعد ملخصاً موجزاً")، بنفس `cwd` و`cfg` وأدوات المنفّذ
    (مع احترام صلاحيات الجلسة)، ثم استخدم `outcome.text` كـ tool-result.
  - **حماية العود**: عدّاد عمق (مثلاً حد 2-3 مستويات) — تجاوز الحد يعيد خطأ
    "تفويض متجاوز للعمق" بدل حلقة لا نهائية. مرّر العمق عبر معامل إضافي.
- الأحداث الداخلية للوكيل الفرعي: إمّا تُبثّ (بوسم `sub` في الـ step) أو تُكتتم —
  القرار التصميمي: **تُبثّ بوسم** (الشفافية أولاً، وثيقة 02) عبر إعادة توجيه
  callbacks الحالية بنفس الطريقة التي يبثّ بها المخطط.

### الخطوة 3 — تعريف الأدوار المتخصصة (أساس صفحة الإعدادات)

أنشئ `core/src/roles.rs` (أو مدخل في config.rs):
- بنية `AgentRole { id, prompt, tools: Vec<String>, max_tool_rounds }`.
- أدوار جاهزة: `coder` (افتراضي)، `tester`، `security`، `docs`، `db`,
  `devops` — لكل منها prompt وأدوات مناسبة.
- ربط اختياري: `idexal-core roles` يعرضها، والخطة 001 (صفحة الإعدادات) تعرضها
  لاحقاً كقوالب وكلاء. **لا تشترط هذه الخطوة على صفحة الإعدادات.**

### الخطوة 4 — اختبارات

- `agent.rs`: اختبار أن `delegate` تُحوَّل لاستدعاء متكرر (مع `run_command` وهمي
  أو بمزود fake — إن لم يتوفر fake، اكتفِ باختبار `parse_delegate_args` واستخراج
  task/context، واختبار حد العمق بدون شبكة).
- `orchestrator.rs`: لا تغيير لازم — المنفّذ يستفيد تلقائياً.

