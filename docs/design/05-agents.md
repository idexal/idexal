# 05 — الوكلاء وأدوارهم | Agents

> Idexal — Agentic IDE. مرجع: [index](README.md)

## الوكيل الواحد (Single Agent)

أبسط وحدة: حلقة محادثة + أدوات. تُشغَّل بـ `idexal-core stream "<مهمة>"` أو من
الواجهة بلا تفعيل "تعدد الوكلاء".

- **prompt النظام**: "Idexal، وكيل برمجة مستقل في مساحة عمل حقيقية. افحص قبل
  التغيير وتحقق بعده. كن موجزًا، أجب بلغة المستخدم."
- **الذاكرة**: تُسترجَع وتُحقن في prompt النظام (لا في رسالة المستخدم).
- **النهاية**: رد نهائي بلا استدعاء أدوات، أو تجاوز `max_tool_rounds`.

## الوكلاء المتعددون (Multi-Agent Orchestration)

البنية: **مخطط ← منفّذون متوازون ← مراجع**. تُشغَّل بـ `idexal-core agent` أو
بمفتاح "تعدد الوكلاء" في الواجهة.

```
                ┌─────────────┐
  مهمة المستخدم │  PLANNER    │  بلا أدوات — تفكير فقط
                └──────┬──────┘
                       │ خطة: [{id, description, depends_on}]
        ┌──────────────┼───────────────────┐
        ▼              ▼                   ▼
  ┌──────────┐  ┌──────────┐        ┌──────────┐
  │EXECUTOR 1│  │EXECUTOR 2│  ...   │EXECUTOR N│  متوازون فعليًا
  │ step 1   │  │ step 3   │        │ step 5   │  (موجات حسب التبعيات)
  └────┬─────┘  └────┬─────┘        └────┬─────┘
       └─────────────┼───────────────────┘
                     ▼
              ┌─────────────┐
              │  REVIEWER   │  أدوات قراءة فقط — تحقق وملاحظات
              └──────┬──────┘
                     ▼
                 الملخص النهائي
```

### المخطط (Planner)
- **الأدوات**: بلا أدوات (التخطيط تفكير، ومنحه أدوات يغرّه بالتنفيذ بنفسه).
- **المخرجات**: مصفوفة JSON صارمة: `[{"id":1,"description":"...","depends_on":[]}]`.
- **القواعد**: خطوات أقل أفضل؛ لا خطوتان تعدّلان نفس الملف بشكل مستقل.
- **المرونة**: إذا لم يلتزم النموذج بالتنسيق، `parse_plan` يستخرج المصفوفة من النص
  (حتى داخل فقرات أو صناديق ```)، ويسقط على أسطر مرقّمة عند غياب JSON.

### المنفّذون (Executors)
- **لكل خطوة**: وكيل مستقل بنظام prompt "منفّذ — نفّذ خطوتك فقط".
- **التوازي الحقيقي**: موجات من الخطوات المستقلّة (لا تبعيات مشتركة) تُشغَّل
  `tokio::spawn`، مقيّدة بـ `max_parallel_agents`.
- **السياق**: كل منفّذ يتلقى المهمة الكاملة + خطوته (id من total).
- **الذاكرة**: كل منفّذ يسترجع قبل الإطلاق (SQLite لا يُشارَك عبر await).
- **نتيجة**: (id, ok, ملخص) تُبث فور انتهاء الخطوة.

### الجدولة (Scheduler)
- تجميع الخطوات إلى **موجات**: كل موجة = خطوات استوفت تبعياتها → تعمل بالتوازي.
- التبعيات الدائرية/الغائبة: تُنفَّذ تسلسليًا في الموجة الأخيرة (لا حلقات، لا فقدان عمل).

### المراجع (Reviewer)
- **الأدوات**: قراءة/سرد فقط (`read_only_definitions`) — يفحص العمل على القرص بلا تعديل.
- **المهمة**: اكتملت المهمة؟ مشاكل حقيقية مع file:line؟ إصلاحات ملموسة؟
- **المخرجات**: تصبح الملخص النهائي (أو تُلحق عند غياب المراجعة).

## وكلاء المستقبل (Subagents)

- **منفّذ يفوّض**: أداة `delegate(task, context)` تشغّل وكيلًا فرعيًا (نفس النواة،
  جولة منفصلة) لمهمة جزئية، ثم يعود بنتيجة موجزة في المحادثة.
- **أدوار متخصصة** (قابلة للإضافة من صفحة الإعدادات):
  - وكيل الكود (default) · وكيل الاختبارات · وكيل الأمان · وكيل التوثيق ·
    وكيل قاعدة البيانات · وكيل DevOps · وكيل تحسين الأداء · وكيل الترجمة.
- **كل دور = ملف تعريف**: system prompt + الأدوات المتاحة + وضع الصلاحيات.
- **مكتبة أدوار**: قوالب جاهزة + "دور مخصص" بكل حرية.

## نظام تعريف الوكيل (المخطط)

```json
{
  "id": "reviewer",
  "prompt": "أنت المراجع...",
  "tools": ["read_file", "list_dir"],
  "maxToolRounds": 6,
  "permissions": "read-only"
}
```

## قاعدة

**كل وكيل جديد يُعرَّف في النواة (اختبارات) ثم يُعرض في صفحة الإعدادات** —
لا مفهوم "وكيل" خارج عقد النواة.
