## المبادئ الحاكمة (Design Principles)

1. **بلا قيود ولا بوابات** — أي مزود، أي نموذج، أي endpoint متوافق مع OpenAI يُضاف
   من صفحة الإعدادات، بلا قائمة بيضاء ولا إعادة تصريف (no code change, no allowlist).
2. **التحكم من داخل البرنامج** — كل إعداد، صلاحية، مزود، نموذج، ووكيل يُدار من
   صفحة الإعدادات الخاصة به. ملف `config.json` هو مجرد أثر مكتوب تلقائياً، لا واجهة استخدام.
3. **حيٌّ وتفاعلي وReal-time** — كل شيء أثناء العمل: بث NDJSON مباشر، قائمة مهام
   تتحدّث لحظياً، Git يعيد القراءة بعد كل أداة، معاينة حية تعيد التحميل.
4. **العقد الموحّد** — واجهة واحدة (NDJSON على stdout) تخدم الغلاف وCLI وأي عميل مستقبلي.
5. **الشفافية** — المستخدم يرى ماذا يفعل الوكيل، بأي مزود، وبأي أداة، في كل لحظة.

## مصطلحات

- **النواة (Core)**: ثنائي Rust `idexal-core` — محرك الوكلاء والمزودين والذاكرة والأدوات.
- **الغلاف (Shell)**: تطبيق Electron — واجهة المستخدم: محرر، طرفية، Git، معاينة، لوحة وكيل.
- **الطرفية (CLI)**: أمر `idexal` — تشغيل الوكلاء من أي محطة، بنفس العقد.
- **المهمة (Task)**: طلب المستخدم — وكيل واحد أو خطة متعددة الوكلاء.
- **الخطوة (Step)**: وحدة تنفيذ في الخطة، قد تعمل بالتوازي مع غيرها.
- **الوكيل (Agent)**: حلقة محادثة + أدوات بنظام prompt محدد (مخطط، منفّذ، مراجع…).
