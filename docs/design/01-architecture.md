# 01 — البنية المعمارية | Architecture

> Idexal — Agentic IDE. مرجع: [index](README.md) · [ADRs](../adr/)

## المبدأ

ثلاث طبقات مستقلة تماماً في وقت التشغيل، تتحاور عبر **عقد واحد**: أسطر NDJSON
على stdout. أي عميل — الغلاف المكتبي، الطرفية، أو مستقبلاً موقع ويب أو إضافة محرر —
يستهلك نفس العقد، فيبقى المحرك واحداً والواجهات متعددة.

```
┌──────────────────────────────────────────────────────────────┐
│  app/  الغلاف المكتبي (Electron + TypeScript + Monaco)        │
│  ├─ main/    index.ts · workspace.ts · terminal.ts            │
│  │           (عمليات الأقراص، المحطات، Git، الاتصال بالنواة)   │
│  ├─ preload/ index.ts  (جسر contextBridge — واجهة صريحة)      │
│  └─ renderer/ index.ts · settings.ts · style.css              │
│              (واجهة المستخدم الكاملة)                          │
└───────────────┬──────────────────────────────────────────────┘
                │ spawn + NDJSON على stdout
┌───────────────▼──────────────────────────────────────────────┐
│  core/  محرك الوكلاء (Rust — ثنائي مستقل)                     │
│  ├─ main.rs         أوامر: stream · agent · providers ·       │
│  │                  config · test · memory · --version        │
│  ├─ config.rs       تحميل المزودين ودمج الملفات والمتغيرات     │
│  ├─ providers/      Registry (fallback + cooldown) ·          │
│  │                  anthropic.rs · openai_compat.rs · types.rs│
│  ├─ agent.rs        حلقة المحادثة + الأدوات                   │
│  ├─ orchestrator.rs مخطط ← منفّذون متوازون ← مراجع            │
│  ├─ tools.rs        read_file · write_file · list_dir ·       │
│  │                  run_command (+ حماية المسار)              │
│  └─ memory.rs       ذاكرة طويلة الأمد (SQLite)                │
└───────────────┬──────────────────────────────────────────────┘
                │ الأمر نفسه من أي محطة
┌───────────────▼──────────────────────────────────────────────┐
│  cli/  طرفية Idexal (Node، بلا تبعيات)                        │
│  bin/idexal.js — يُشغّل النواة ويعرض الأحداث بألوان وشكل TUI   │
└──────────────────────────────────────────────────────────────┘
```

## عقد NDJSON

النواة تُخرج كل حدث في سطر JSON مستقل. هذا هو **الواجهة العامة الوحيدة**:

| الحدث | المعنى |
|-------|--------|
| `{"type":"start","providers":[...]}` | بدأت الجولة وسلسلة المزودين الصالحة |
| `{"type":"provider","name":"anthropic"}` | المزود الذي يُجرَّب الآن |
| `{"type":"delta","text":"..."}` | جزء نصي مُبث مباشرةً من النموذج |
| `{"type":"tool-call","name","args","step"?}` | الوكيل طلب أداة |
| `{"type":"tool-result","name","ok","output","step"?}` | نتيجة الأداة |
| `{"type":"phase","phase":"planning"}` | مرحلة تعدد الوكلاء (planning/executing/reviewing) |
| `{"type":"plan","steps":[{id,description,depends_on}]}` | خطة المخطط |
| `{"type":"step-start"/"step-end","id","ok","summary"}` | بدء/انتهاء خطوة منفّذ |
| `{"type":"review","text"}` | ملاحظات المراجع |
| `{"type":"done","summary","provider","tool_rounds"}` | اكتمال المهمة |
| `{"type":"error","error"}` | فشل (كل المزودين مثلًا) |

### سبب هذا التصميم

- **بث مباشر**: الغلاف يرسم كل حدث فور وصوله، فلا انتظار لنهاية الجولة.
- **قابلية الإضافة**: حدث جديد لا يكسر العملاء القدامى (سطر إضافي فقط).
- **حدود نظيفة**: النواة بلا حالة واجهة؛ الغلاف بلا منطق ذكاء.
- **توافق ABI**: لا FFI ولا native addon — تجنّب كامل لمشاكل توافق Electron/Rust
  (مصدر ADR 0001).

## إدارة الحالة

| الحالة | أين تعيش | من يملكها |
|--------|----------|-----------|
| المزودون والنماذج والوكيل | `~/.idexal/config.json` + `./idexal.config.json` + متغيرات البيئة | `config.rs` (دمج بالأولوية: ملف ← ثم متغيرات) |
| الذاكرة طويلة الأمد | `~/.idexal/memory.db` (SQLite) | `memory.rs` |
| نافذة/محطات/جلسات طرفية | ذاكرة عملية Electron | `app/src/main/*` |
| تبويبات الملفات ونماذج المحرر | ذاكرة الـ renderer | Monaco |
| جلسات الوكلاء | لا تُحفظ (جولة عابرة) — الملخص يُرسل للذاكرة فقط | `agent.rs` / `orchestrator.rs` |

## أوامر النواة (السطح الحالي والمستقبلي)

```
idexal-core stream "<مهمة>"                وكيل واحد (بث NDJSON)
idexal-core agent  "<مهمة>"                تعدد وكلاء: مخطط ← منفّذون ← مراجع
idexal-core providers                      قائمة المزودين وحالتهم
idexal-core config                         الإعداد الفعلي كاملًا كـ JSON (بلا مفاتيح)
idexal-core test <provider-id>             فحص اتصال حي لمزود واحد
idexal-core memory stats|recall|add        إدارة الذاكرة
idexal-core --version
```

> `config` و`test` هما عقد صفحة الإعدادات في الغلاف: التحميل من الأول، والتحقق
> من الاتصال بالثاني — والمفتاح الحقيقي لا يمر عبر أي منهما إلى الواجهة.

## التبعيات المعمارية (قاعدة صارمة)

1. `core/` لا يعرف شيئاً عن Electron ولا عن الواجهة — مخرجه نصي فقط.
2. `app/` لا يحتوي أي منطق ذكاء — فقط عرض وتنظيم.
3. `cli/` غلاف عرض فحسب — لا تكرار لمنطق النواة.
4. أي ميزة جديدة: تُنفَّذ في النواة أولاً (قابلة للاختبار)، ثم تُعرض في الغلاف والطرفية.
