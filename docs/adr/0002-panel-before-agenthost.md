# ADR 0002 — لوحة Idexal خفيفة أولاً، ثم تكامل AHP/agentHost لاحقاً

**الحالة:** مُعتمَد | **التاريخ:** 2026-08-03

## السياق

`src/vs/platform/agentHost/` هو النظام الأصلي في VS Code لاستضافة وكلاء خارجيين
(Claude Agent SDK، Codex CLI، GitHub Copilot CLI) كخلفيات (backends) قابلة للتوصيل عبر
بروتوكول حقيقي ومُوثَّق بالإصدار (AHP — Agent Host Protocol) فوق WebSocket + lockfile.
حجمه ضخم: 1,286 ملف TypeScript، 247,153 سطراً، مع IPC channels كاملة
(`AgentHost`, `Logger`, `ConnectionTracker`, `Protocol`, `Management`, `RemoteProxy`)
وbroker حالة بروتوكول (`common/state/protocol/**`) وملف إصدار بروتوكول
(`.ahp-version`). الجانب المقابل في CLI بلغة Rust (`cli/src/commands/agent*.rs`،
~3,464 سطراً) يطبّق فعلياً عميل/خادم AHP عبر crates خارجية منشورة (`ahp`, `ahp-types`
الإصدار 0.4) — لكن toolchain لغة Rust غير مثبت على هذه الآلة حالياً، وتثبيته (rustup +
OpenSSL عبر vcpkg على ويندوز) خطوة بيئة نظام منفصلة.

هذا هو المسار الاستراتيجي الصحيح على المدى الطويل: تكامل AHP الكامل يجعل Idexal يظهر
كخلفية أصلية داخل واجهة الوكلاء المدمجة في VS Code (نفس المكانة التي تحتلها Claude
وCodex)، بدل واجهة منفصلة مبنية يدوياً.

لكن البدء به مباشرة يعني تحمّل تعقيد ضخم (DI الخاص بـ VS Code، IPC channels، حالة
البروتوكول، توليد lockfile، مصادقة device-flow) **قبل** أن يكون لدينا حتى تطبيق يعمل
مرئياً للمستخدم يمكن اختباره والبناء عليه — وهو ما طلبه المستخدم صراحة كخطوة أولى
("شغّل البرنامج لنختبره مرئياً").

## القرار

نبني أولاً امتداد/لوحة "Idexal Agent" بسيطة (تشبه نمط الامتدادات المدمجة الأخرى في
`extensions/`) تستدعي `idexal/ai-core/src/cli.ts` مباشرة كعملية Node فرعية (وضع
`stream --json`)، وتعرض أحداثه (NDJSON) في واجهة دردشة/لوحة جانبية مخصصة. هذا لا يحتاج
Rust على الإطلاق ويمكن تطويره واختباره بصرياً فوراً بعد أول بناء ناجح للتطبيق.

تكامل AHP الكامل (بحيث يظهر Idexal كخلفية أصلية في نظام الوكلاء بمحرك VS Code، مستضافاً
عبر `idexal agent host` بلغة Rust) يبقى هدفاً موثّقاً في ROADMAP.md (ضمن المرحلة 3/4)،
يُنفَّذ بعد استقرار اللوحة الأولى وتثبيت Rust toolchain.

## الأثر

- لا حاجة لتثبيت Rust أو حل مشاكل vcpkg/OpenSSL قبل رؤية أول نتيجة مرئية للمستخدم.
- اللوحة الأولى ستكون أبسط تقنياً (بدون IPC/lockfile/device-flow) لكنها ستحتاج إعادة
  هيكلة جزئية لاحقاً عند الانتقال لتكامل AHP الكامل — مقايضة مقبولة لصالح السرعة
  والتحقق المبكر.
