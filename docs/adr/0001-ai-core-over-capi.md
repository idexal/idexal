# ADR 0001 — استخدام Idexal AI Core بدل حلقات Copilot CAPI كنواة للوكلاء

**الحالة:** مُعتمَد | **التاريخ:** 2026-08-03

## السياق

المستودع يحتوي على امتداد GitHub Copilot Chat الكامل (`extensions/copilot/`، نحو 641
ألف سطر) وفيه حلقات وكيل ناضجة وتعمل فعلياً (`executionSubagentToolCallingLoop.ts`،
`searchSubagentToolCallingLoop.ts`، مبنية على `toolCallingLoop.ts` — 2,431 سطراً من
البنية التحتية الحقيقية). كان يمكن اعتبارها نقطة الانطلاق الطبيعية لبناء وكلاء Idexal.

لكن المراجعة العميقة أظهرت أن حلقات الوكيل الرئيسية في هذا الامتداد تتحلّل افتراضياً
إلى `CopilotChatEndpoint`، الذي يتطلب:
- مصادقة عبر حساب GitHub وتبادل رمز Copilot (`copilotTokenManager.ts`) — أي اشتراك
  GitHub Copilot فعلي.
- الاتصال عبر حزمة خاصة غير مفتوحة المصدر `@vscode/copilot-api` (غير موجودة فعلياً في
  هذا المستودع، فقط تعريف أنواع `.d.ts` بديل) إلى خوادم GitHub الخاصة (CAPI).

هذا يتعارض مباشرة مع رؤية Idexal: منتج **حر بدون قيود**، متعدد المزودين بالكامل،
لا يعتمد على اشتراك أو بنية تحتية مملوكة لجهة ثالثة.

في المقابل، `idexal/ai-core/` (نواة مبنية مسبقاً في هذا المشروع، ~11,400 سطر Node
خالص بدون تبعيات) توفّر فعلياً ومُختبرة (33 اختباراً حقيقياً): مزودين متعددين
(Anthropic + أي مزود متوافق مع OpenAI)، Fallback تلقائي، تنسيق وكلاء
(planner→executor→reviewer)، ذاكرة SQLite طويلة المدى مع استرجاع دلالي، وأدوات وكيل
مع حماية مسار مُختبرة — دون أي اعتماد على GitHub أو أي حساب.

كما توجد طبقة BYOK داخل نفس امتداد Copilot (~7,200 سطر) تتصل مباشرة بـ
Anthropic/OpenAI/Gemini/Ollama بدون حساب GitHub، وهي بديل ممكن نظرياً، لكنها مصممة
كموفّر نموذج لـ `vscode.LanguageModelChatProvider` ضمن بنية الامتداد بأكملها (DI،
telemetry، إلخ) — عمل إعادة هندسة أكبر من الاستفادة من `ai-core` الجاهزة والمستقلة.

## القرار

نواة الوكلاء الرسمية لـ Idexal هي `idexal/ai-core/` — وليس حلقات `extensions/copilot`.
امتداد Copilot الحالي يبقى في المستودع (ترخيصه MIT الأصلي محفوظ) كمرجع لإعادة استخدام
مكوّنات واجهة محددة (مثل أدوات عرض الـ diff) عند الحاجة، لكن **الاتصال الفعلي بالنماذج
والتنسيق بين الوكلاء يمر حصراً عبر `ai-core`**.

## الأثر

- لوحة/امتداد "Idexal Agent" الجديدة (المرحلة 3 من الخطة) ستستدعي
  `idexal/ai-core/src/cli.ts` مباشرة (Node، دون حاجة لأي مصادقة GitHub) بدل تفعيل
  chat participant مبني على `toolCallingLoop.ts`.
- استبدال/إزالة الاعتماد على `extensions/copilot` بالكامل يبقى قراراً مستقبلياً
  منفصلاً (مرتبط بالمرحلة 5 في ROADMAP.md) — لا داعي له الآن لأن `ai-core` يعمل بجانبه
  دون تعارض.
